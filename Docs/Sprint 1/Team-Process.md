# Team Process

## Workflow
- CareerConnect work is divided into user stories and smaller tasks based on the features we plan to develop.
- Tasks are assigned to team members based on the part of the project they are working on.
- For Sprint 1, the team was divided into three development groups: registration/profile, resume management, and general website UI.
- Team members work on their assigned tasks and use GitHub to keep track of the project and changes.
- Progress, problems, and important changes are discussed during team meetings.

## Branching Strategy
- The `main` branch is used for the stable version of CareerConnect.
- Team members create separate branches when working on features or making changes.
- Branch names should describe the feature or task being worked on.
- Work is merged into `main` after it is completed and reviewed.

## Pull Request Process
- When a feature or task is completed, the team member creates a pull request before merging it into `main`.
- The pull request explains the main changes that were made.
- Another team member reviews the changes before they are merged.
- If a problem is found, the changes are updated before the pull request is approved.

## Code Review Process
- At least one other team member reviews the code before it is merged into `main`.
- The reviewer checks that the code works and matches the requirements of the task.
- The reviewer also checks for mistakes or problems that could affect other CareerConnect features.
- Any required changes are made before the code is approved and merged.

## Definition of Ready
A CareerConnect user story or task is ready to be worked on when:
- The goal and requirements are clear.
- The expected feature or change is understood.
- The task has enough information for development to begin.
- The task has been assigned to a team member.

## Definition of Done
A CareerConnect user story or task is done when:
- The required feature or change has been completed.
- The feature has been tested and works as expected.
- The work has been reviewed by another team member.
- Any problems found during review have been fixed.
- The completed work has been merged into the project.
