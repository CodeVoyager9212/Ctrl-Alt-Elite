# Sprint 2 Planning

## Sprint Goal
The goal of Sprint 2 is to continue developing CareerConnect by improving the features from Sprint 1 and adding new features to help users find jobs and manage their applications.

For development, the team will focus on completing profile and resume management, job search and filtering, and job application submission and tracking. The team will also begin working on the recruiter dashboard, which will be completed in Sprint 3.

## Sprint Backlog
- Review and improve the features developed during Sprint 1.
- Complete profile and resume management.
- Develop the job search and job listing interface.
- Implement job application submission and tracking.
- Begin developing the recruiter dashboard and job posting features.
- Create user stories, tasks, and acceptance tests in GitHub.
- Set up a Continuous Integration (CI) pipeline.
- Update the required Sprint 2 documentation.
- Test and review the completed features before submission.

## Priorities
- **High:** Profile and resume management, job search and filtering, job application submission and tracking, acceptance tests, Continuous Integration setup, and required Sprint 2 documentation.
- **Medium:** Improvements to the website interface and starting the recruiter dashboard.
- **Low:** Additional CareerConnect features that are not required to be completed during Sprint 2.

## Effort Estimation
The team uses three levels to estimate the effort needed for each task:
- **Low:** Small tasks that can be completed quickly.
- **Medium:** Tasks that require more coding, testing, or teamwork.
- **High:** Larger tasks that take more time and involve several development steps.

## Team Capacity
The team has six members. For Sprint 2 development, the team is divided into two groups of three:

- **Group 1 – Arman, Peter & Philopater:** Job Search and Job Listing Interface.
- **Group 2 – Alfred, Anas & Omar:** Job Application Submission and Tracking.

Team members also help with improving existing features, acceptance testing, GitHub management, documentation, and reviewing the completed work.

## Risks
- Some features may take longer to complete than planned.
- Combining work from different team members may cause code conflicts.
- Team members may have different schedules and availability.
- Problems with the database or connections between features may delay development.
- Testing may reveal bugs that need additional time to fix.
- Some tasks may need to be changed after reviewing the project requirements.
